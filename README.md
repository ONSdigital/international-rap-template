# Reproducible analytical pipeline repository template for international projects

## About 
This is a template for creating a simplified version of a reproducible analytical pipeline, specifically designed with international stakeholders in mind. It provides a structured approach to organising code, data, and documentation, ensuring that all components are easily understood.

## Repository Structure

```plaintext
README.md
data/
demonstrtation_data/
│   ├── input_data.xlsx
outputs/
scripts/
│   ├── validation_modules.py      
│   └── processing_modules.py      
data_input_validation.py         
main_pipeline.py
readme_template.md
LICENSE
```
- `data/`: Contains input data files and outputs generated by the scripts. This folder is intended to be populated by the user and is not included in version control.
- `demonstration_data/`: Contains example input data files to demonstrate the pipeline's functionality.
    - `input_data.xlsx`: An example input data file used to demonstrate the pipeline's functionality.
 - `outputs/`: This folder is intended to store output files generated by the pipeline. It is not included in version control to avoid cluttering the repository with generated files.   
- `scripts/`: Contains Python modules for data processing and validation.
    - `validation_modules.py`: Contains functions for validating data inputs, ensuring that they meet the required standards before processing.
    - `processing_modules.py`: Contains functions for processing data, including cleaning, transforming, and preparing it for analysis.
- `readme_template.md`: A readme template designed to be modified by the user to provide an overview of the project, its purpose, and main features.
- `data_input_validation.py`: This script serves as one of the master scripts of the pipeline. It is run before `main_pipeline.py` to ensure that all data inputs are validated before processing.
- `main_pipeline.py`: This script serves as the main script of the pipeline, after data
validation has been handled.
- `LICENSE`: This project is licensed under the MIT License - see the [LICENSE](LICENSE) file for details.

## Usage
### Setting up the new repository
This template is intended to cloned using the "Use this template" button on the top right of the repository main page on the browser. This will replicate the repository into your own GitHub account, without the history of this repository.

We recommend using Visual Studio Code (VS Code) as your code editor. You can download it from [here](https://code.visualstudio.com/). VSCode provides a user-friendly interface which is suitable for both beginners and experienced developers, and can be set up to use version control with Git and GitHub.

Once you have the repository in your own GitHub account, you can clone it to your local machine using the following command:

```bash
git clone <your-repository-url>
```

You can then open the project in VS Code by going to `File > Open Folder` and selecting the cloned repository folder.

### Virtual environments
You should also create a virtual environment for your project. Virtual environments are isolated Python environments that allow you to install packages and dependencies specific to your project, without affecting any other Python projects you are working on. This helps prevent conflicts between package versions and ensures that your project remains reproducible and easy to maintain.

We recommend using `venv` for this purpose. To set up a virtual environment using `venv`, follow these steps:
1. Open your terminal or command prompt in VSCode.
2. If you have your project open in VSCode you should already be in your project directory, otheriwse navigate to it.
3. Run the following command to create a virtual environment named `venv`:
   ```bash
   python -m venv venv
   ```
4. Activate the virtual environment in VSCode:
   - On Windows:
     ```bash
     .\venv\Scripts\activate
     ```
   - On macOS and Linux:
     ```bash
     source venv/bin/activate
     ```
5. Once the virtual environment is activated, you can install the required packages using the `requirements.txt` file. The virtual environment will have to be acivated each time you start a new terminal session in VSCode.

### Modifying files to suit your project
1. **Readme Template**: Modify the `readme_template.md` file to provide an overview of your project, its purpose, and main features. Rename it to `README.md` after editing.
2. **Data Folder**: Populate the `data/` folder with your input data files.
3. **Scripts Folder**: Update the scripts in the `scripts/` folder to include your data processing and validation logic and delete the example code.
4. **Main Scripts**: Modify `data_input_validation.py` and `main_pipeline.py` to orchestrate your data validation and processing workflow.
5. **Configuration**: Update the `config.py` file to set paths and parameters specific to your project. The configuration file is where you can set parameters that might change based on the environment or specific use cases, such as file paths, thresholds, or other settings that the user might want to adjust without modifying the core logic of the scripts.


## Running the example
The example has been set up to demonstrate how a pipeline like this could work. It uses example data located in the `demonstration_data/` folder.

### Prerequisites for example data
The Python version used to run the example data in this template is 3.12.
The packages required to run the example data through the pipeline are listed in `demonstration_requirements.txt`. You can install them using pip:

```bash
pip install -r demonstration_requirements.txt
```

### Running the pipeline
To run the example pipeline, follow these steps:
1. Ensure you have the example data in the `demonstration_data/` folder.
2. Run the data validation script:
   ```bash
   python data_input_validation.py
   ```
3. The validation script will find missing values in the example data and print warnings to the console. It will create a new file called `input_data_revisedXXXXXXXX.xlsx` in the `demonstration_data/` folder, where `XXXXXXXX` is a timestamp. 
4. Open this file and delete the rows with missing values. This is to simulate the process of correcting data issues before running the main pipeline. Save and close the file.
5. Open the `config.py` file and update the `revised_data_path` variable to point to the revised file you just saved.
6. Run the main pipeline script:
   ```bash
   python main_pipeline.py
   ```
7. The main pipeline script will process the revised data and save the results to `data/output_results.xlsx`.
